Studio Preflight

Protect what can't be replaced, restrict what the agent can reach, install the smallest thing that works, then render one portrait. Every phase ends with a check you run yourself.

A Protect · 25 min B Restrict · 15 min C Install · 30 min + downloads D Render · the point

A · Protect

Do first · no agent software yet
A1

Inventory what cannot be re-downloaded

Test each folder: could you get it back off the internet? Games yes, so skip them. Save files, documents, photos, project folders, no. List the survivors in Notepad. Expect megabytes, not gigabytes; that number is what makes the rest of this phase cheap.

The drive: G:, the 750 GB USB disk. It stays unplugged between runs, which makes it immune to anything running on the PC, ransomware included. Your exposure is the gap between runs, so pick a cadence you will actually keep (A5).

A second external drive only buys cover against this drive dying. Worth adding once the habit sticks; not worth blocking phase B on today.

A2

The archive script

Every run writes a full copy into a folder named for today’s date: G:\Backup\2026-08-29\. The date folders are the version history, so nothing needs a service, a scheduler, or a version database. Restore is copy-and-paste in Explorer.

Open Notepad, paste the script below, then File → Save as → Desktop → filename weekly-archive.bat → Save as type: All Files. Miss that last setting and Windows saves it as weekly-archive.bat.txt and nothing will run.

@echo off
setlocal

rem --- 1. destination drive letter
set DRIVE=G:
set ROOT=%DRIVE%\Backup

rem --- 2. copy flags. For a PREVIEW that writes nothing,
rem        comment out the first line, uncomment the second.
set FLAGS=/E /R:1 /W:1 /XJ /NP
rem set FLAGS=/E /R:1 /W:1 /XJ /L

if not exist "%DRIVE%\." (
  echo.
  echo   Drive %DRIVE% is not there.
  echo   Plug it in, or change DRIVE at the top of this file.
  echo.
  pause
  exit /b 1
)

for /f %%d in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd"') do set STAMP=%%d
set DEST=%ROOT%\%STAMP%

echo.
echo   Destination: %DEST%
echo.

robocopy "%USERPROFILE%\Documents" "%DEST%\Documents" %FLAGS%
robocopy "%USERPROFILE%\Desktop"   "%DEST%\Desktop"   %FLAGS%
robocopy "%USERPROFILE%\Pictures"  "%DEST%\Pictures"  %FLAGS%

rem --- 3. game saves: paste the folder from A4, then delete the rem
rem robocopy "PASTE_SAVE_FOLDER_HERE" "%DEST%\Saves" %FLAGS%

echo.
echo   Finished. Scan the output above for a non-zero FAILED column.
echo   Folder: %DEST%
echo.
echo   Retention: delete whole dated folders in Explorer when the
echo   drive fills. Nothing else points at them.
echo.
pause
FlagWhat it does
/ECopy subfolders, including empty ones
/R:1 /W:1Retry a failed file once, wait 1 second. The default is a million retries at 30 seconds each
/XJSkip junction points, which otherwise loop forever
/NPNo per-file percentage spam
/LList only. Copies nothing. The dry-run

No /MIR, on purpose. Mirroring makes the copy match the source, so a file you delete by accident on Monday is gone from the backup by Sunday. Dated folders never delete anything.

First run: use the /L line. Swap the two FLAGS lines, double-click the file, and read what scrolls past. It lists what it would copy and writes nothing at all. When the list looks like your A1 inventory and not like your entire disk, swap the lines back and run it for real.

A3

Restore test verify

Five minutes, no waiting, no progress bar to stare at. What you do here is exactly what a real restore looks like, which is the point of doing it.

  1. Make the bait file. Right-click empty Desktop → New → Text Document, name it restore-test.txt. Open it, type the current clock time (14:07 test), save, close. Real text matters: an empty file can come back empty and teach you nothing.
  2. Run the script. Plug in G:, double-click weekly-archive.bat, wait for Finished, press a key to close the window.
  3. Destroy the original. Delete restore-test.txt from the Desktop, then right-click Recycle Bin → Empty Recycle Bin → Yes. Skip the emptying and the file is still on C:, so the test proves nothing about G:.
  4. Restore it. Open File Explorer → G:\Backup\ → today’s dated folder → Desktop\. restore-test.txt is sitting there. Copy it, paste it back on the Desktop. That is the restore.
  5. Confirm. verify Open it. It shows the clock time you typed in step 1. A file that comes back empty, or carrying the wrong contents, counts as a failure.

File doesn’t come back = you have no backup. Stop here. Everything downstream assumes this passed. Tell me which numbered step broke and what the screen said.

A4

Game saves: locate, then wire in

Find the real folder. Play 2 minutes → save → quit → sort by Date modified inside Steam\userdata\, Documents\, and %LOCALAPPDATA%. The folder that changed in the last five minutes is yours. Guessing from a wiki gets the wrong folder often enough to be worth these two minutes.

Wire it in. Right-click weekly-archive.bat → Edit (or Open with → Notepad). Find the line starting rem robocopy "PASTE_SAVE_FOLDER_HERE". Replace the placeholder with your folder path, then delete the leading rem so the line runs. Save.

Run the script. verify that G:\Backup\today\Saves\ exists and the file timestamps in it match the session you just played.

Steam Cloud is a fine third copy where a game supports it (Steam → Settings → Cloud, then per game Properties → General), but quotas apply and coverage is per-game. Treat it as a bonus, never as the backup.

A5

Cadence and retention

Sunday, phone reminder. Plug in G:, double-click, wait, unplug. The script is reliable; remembering is the part that fails, so put it in the phone rather than in your head.

Growth: a full copy every week at your A1 size of megabytes lands in single-digit gigabytes a year. On a 750 GB disk that is years of runway before you have to think about it.

Retention is manual and deliberately dumb: when the drive fills, open G:\Backup\ and delete whole dated folders, oldest first, in Explorer. Nothing indexes them, nothing points at them, so nothing breaks. No script deletes anything on your behalf.

Unplug G: when the run finishes. A drive that is not connected cannot be encrypted by ransomware, wiped by a bad command, or written to by anything running as jep in phase B. That disconnection is doing as much work as the copying is.

B · Restrict

Only when you've decided on Pi
B1

Create the jep account

Settings → Accounts → Other users → Add account → I don't have this person's sign-in information → Add a user without a Microsoft account.

Standard user. Never Administrator. An admin account overrides file permissions, which deletes the entire point of this phase.

B2

Grant one folder only

Create D:\work on neither Drive A nor B. Right-click → Properties → Security → Edit → give jep full control of that folder and nothing else. Sign in once as jep to build the profile.

B3

Three denial tests verify

Signed in as jep, all three must fail:

  • Open your main account's Documents → access denied
  • Open the game-save folder → access denied
  • Create a file on Drive A → write refused

Any success means permissions aren't what you think, and the account is giving false confidence. Better to learn that now.

C · Install

Pi as jep · ComfyUI in your main account · native Windows, no WSL2
C1

Prerequisites: check first, install only what is missing

Two pieces, both ordinary user-space installers. Neither is a service or a driver. Do this signed in as jep, because that is the account Pi will run in.

Open a terminal: Win → type cmd → Enter. Run each check, then act on what it prints.

node --version
git --version

Pi runs its shell commands through Git Bash on Windows, which is why Git is a requirement rather than a nicety. Nothing here asks you to use Git yourself.

C2

Install Pi, then find its folder

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

--ignore-scripts blocks any install-time script a package might carry. Pi ships none, so this costs nothing and closes a common supply-chain route. Roughly 147 MB. No service, no startup entry, no Task Scheduler task; Pi runs only while a terminal is open.

Confirm it landed:

pi --version

A version number means you are done. 'pi' is not recognized means npm’s global folder is not on PATH: close the terminal, open a new one, try again.

Create the config folder by running Pi once. Type pi, press Enter, wait for it to start, then type /exit and press Enter. That first run writes the folder you will edit in C3.

Where that folder is. The docs write it as ~/.pi/agent/. The ~ means "the signed-in user’s home folder", so on your machine, signed in as jep, it is:

C:\Users\jep\.pi\agent\

To open it without hunting: press Win+E for File Explorer, click the address bar at the top, type the line below, press Enter.

%USERPROFILE%\.pi\agent

Folders whose name starts with a dot are ordinary folders that some tools hide by convention. If .pi seems missing, turn on View → Show → Hidden items in Explorer. While you are there also turn on View → Show → File name extensions, which you will need in C3.

C3

Set the default to read-only verify

Pi ships with every tool enabled and no sandbox, by design. The file below decides what Pi can do when you launch it by typing pi with no flags. You are setting that default to the harmless end of the range and reaching for more only when a task needs it.

The point is removal rather than approval. A tool that was never loaded cannot be invoked, so there is no prompt to click through and no habit of clicking yes.

Create the file. Open Notepad, paste the block below exactly, then File → Save as. In the Save dialog, click the address bar and type %USERPROFILE%\.pi\agent then Enter. Set File name to settings.json, set Save as type: All Files, leave Encoding as UTF-8, and Save.

{
  "defaultTools": ["read", "grep", "find", "ls"],
  "defaultProjectTrust": "ask",
  "quietStartup": true
}

Line by line: defaultTools lists the only tools loaded at startup, all four of which just look at things. defaultProjectTrust set to ask means Pi asks before it loads instruction files out of a folder you have not approved. quietStartup trims the banner.

Notepad will try to save it as settings.json.txt. That is why Save as type: All Files matters, and why you turned on file name extensions in C2. Look at the file in Explorer: the name must read settings.json and nothing more. If it reads settings.json.txt, rename it and delete the .txt.

Verify it took effect. Run pi, then type /settings and press Enter. Your values should be reflected there. Then ask it to do something it must refuse:

pi "run the command: dir"

It should tell you it has no tool for running commands. verify If it actually runs dir and shows you a folder listing, the file is not being read: check the name for a hidden .txt, and check it sits in C:\Users\jep\.pi\agent\ rather than somewhere else.

Reaching for more, one session at a time. The settings file is the floor. These flags raise it for a single run and change nothing permanently.

Later, a maintained tool_call guard extension adds a second layer that can block an individual call. Treat it as a speed bump behind the wall, and remember rule of three before you install one.

C4

ComfyUI, in your main account

Sign out of jep and back into your own account first. Everything in this step happens there. Two reasons: your GPU session lives in your main account, and ComfyUI has no password, so you want it owned by you rather than by the restricted account.

Which one to download

Comfy Desktop. Take the installer, skip the portable archive. Desktop installs its own private copy of Python during setup, so the Python question disappears: you never check a version, never install Python, never touch a virtual environment. The portable build is the one that expects you to manage Python yourself.

Get the .exe from comfy.org, or from the Comfy-Org/desktop releases page on GitHub. If either ever asks for an email or an account before downloading, stop and use the other one.

Budget the disk before you start. The application is about 4.85 GB, and the Python environment it builds is roughly 15 GB more, so plan on 20 GB for this step alone. The installer asks you to choose a location; point it somewhere with room and not at G:.

Installing

Run the .exe, accept the prompts, choose the install location when asked, and let it finish building the Python environment. That build is the slow part and it runs once. Launch it afterwards from the Start Menu.

verify ComfyUI opens and shows a node graph. Look at the address it is serving on, normally http://127.0.0.1:8188. Write that number down; C5 and phase D both use it.

What 127.0.0.1 means, and why it matters here

127.0.0.1 is the address a computer uses to talk to itself. It is also called loopback, because traffic sent there loops back inside the machine and never reaches the network card. A program listening on 127.0.0.1:8188 is reachable from this PC and from nowhere else: not your router, not your laptop, not the internet.

The consequence that makes this plan work: "this PC" includes every account on it. So jep, which cannot open a single one of your folders, can still send requests to ComfyUI on 127.0.0.1:8188. The agent asks ComfyUI to render, then collects the finished image back through that same connection. It never needs read access to your disk, which is exactly why phase B could be as strict as it was.

ComfyUI has no login and no password. Anything that can reach the port can drive it fully. Loopback is what keeps that safe, so never forward port 8188 on your router and never bind ComfyUI to 0.0.0.0. To reach it from the laptop later, tunnel over SSH, which carries the connection inside an encrypted link rather than opening the port to the network.

D · Render

The only step that proves anything
D1

One DECADEnts portrait, by hand

Pull one entry from the Character Visual Dictionary you wrote in December, the 1990s CRT-head or the 2020s toddler, and render it in that decade’s own film stock. By hand in ComfyUI. No Pi, no automation, no workflow.

Looks right → you know more than any further research could have told you. Looks wrong → you spent 30 GB and an evening, and you found that out in one night rather than one month.

D2

Generate many, select one, refine that one

Compute buys the texture half of the quality gap and none of the decision half. Candidates are cheap at 8 steps; refinement is the expensive pass, and it only pays on an image whose composition is already right. So the order matters: generate a batch, pick your favourite, then refine only that.

The refinement chain, all permissively licensed, in order:

Denoise above 0.35 redraws linework and drifts the style. That single number is what ruins stylised art, because at that strength the model stops enhancing your image and starts reinterpreting it. For faces, use Impact Pack FaceDetailer with your own base model. Avoid GFPGAN and CodeFormer: both are non-commercial, and both are trained on photographs, so they push a stylised face toward a real one.

Watchdog: if ComfyUI’s console prints "support for non commercial upscale models", its loader has picked up spandrel_extra_arches and a restricted architecture is in play. The base spandrel package ships permissive architectures only.

D3

Only then, connect Pi to ComfyUI

A Pi extension of roughly 150 lines of TypeScript, talking to ComfyUI’s HTTP interface on 127.0.0.1:8188, the address from C4. Four tools: run, status, outputs, node_info. No extra Python process, no MCP adapter, no third layer between them.

Consider the first-party Comfy-Org/comfy-mcp later, and only if installing models and nodes becomes the thing slowing you down.

Fill slots, do not let it build graphs. Export a working ComfyUI workflow as a template with named blanks, and let the agent fill in a prompt or a seed. Agents reliably mangle hand-written node JSON. If it ever must edit a graph, have it read /object_info from the live server first so it is working from what that server actually has rather than from memory.

The agent can confirm a file exists and is not empty. It cannot judge whether the image is good. Selection stays yours.

D4

Rule of three

Nothing new gets installed, whether model, extension, skill or subagent, until the same friction has bitten three times. First two weeks: zero config.

Refinement · what compute actually buys

The texture half, not the decision half. Refinement adds micro-detail, fixes softness, kills compression mush, raises resolution. It cannot re-plan a composition, fix six fingers (a detailer re-rolls the region and usually produces a different wrong hand), correct prompt adherence, hold identity across images, or render text. In 2026 the open-versus-closed gap is mostly that second category, so expect refinement to close the fidelity portion and leave structure untouched. Generate many, select one, refine that one.

Caveat: no current measured benchmark for the open/closed gap was verifiable, so that split is mechanistic reasoning rather than a number.

Within a clip under 5 s: solved. Across clips: the wall. Hosted currently wins decisively, and Wan 3.0 shipped API-only, so the frontier closed again. Check whether your Google plan includes Flow before spending a weekend locally. Local earns its place for one thing money can't buy - a LoRA trained on your characters, so the CRT-head is reliably that CRT-head.

Finishable: a 60–90 s stylised piece. Not finishable: a dialogue scene, any held shot past 5 s, a recurring photoreal human, the trilogy. DECADEnts is on the right side of that line by design, not by luck.

Standing rules

A backup the agent can write to is not a backup. Phase B is what makes Phase A real.

Sync is not backup. Mirroring propagates deletion. Version history is the difference.

An unverified backup is a rumour. Re-run the A3 restore test quarterly.

Removing a capability beats blocking it. No bash, no destructive command, nothing to approve.

An ungated mirror does not launder a restrictive licence. Neither does a permissive wrapper.

Compute buys texture, never composition. Generate many, select one, refine that one.

Infrastructure doesn't travel. The cron layer stays on the laptop, where it has run healthy for months.

If a month passes with a research corpus and a plan but nothing rendered, this went the way of the other four.

One thing is deliberately unasserted and marked check first: where your game saves actually live. Confirm it at the machine, in A4.

Ticks are stored in this browser only.

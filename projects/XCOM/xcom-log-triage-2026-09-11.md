# XCOM 2: first log triage under read access, and the Reddit thread read in full

## 1. Correction on the thread

Idi dropped the full thread as text (3,278 lines, `projects/XCOM/REDDIT You can now mod ANY game.txt`). Read whole. My earlier "relevance low" was wrong on the part that matters. The thread's decompilation angle is irrelevant to XCOM 2, which ships its script source with the SDK. The transferable pattern is the other one, stated by several commenters from their own projects: an agent with the game's files, a log, and a test loop becomes a personal mod engineer that patches the mods you run, changes values you dislike, and adds features on demand. Concrete cases in the thread: a Battle Brothers player had Claude write a bug report for the Legends mod and then the patch itself, without waiting for the mod author; a BSG Deadlock player changed ammunition and armor values with zero game-dev knowledge; the OP's Prey mod and Touhou framerate patch were one-shot then refined, under a plus-tier subscription, with the OP judging Sonnet unable and Opus needing babysitting. Working notes from the thread: pair the agent with IDA or x64dbg MCP servers for binaries; run plan mode and bounce the plan between models; keep the agent sandboxed because it can corrupt the OS; expect heavy human testing (the PS1 Legend of Legaia project, half a year in, still needs savestates and manual runs). Two commenters push back on "solved": Prey has an open engine and Touhou has prior reverse-engineering projects, and human-in-the-loop is still required for deep call stacks. All of this is anecdote from named strangers; none of it is measured.

For XCOM 2 the pattern lands harder than in the thread: no reverse engineering, source available, config-only mods need no compiler at all, and the game writes a verbose error log every session. Section 3 is that pattern applied once.

## 4. How the fixes get applied, three routes

- A. Edit the two workshop files in place (8 lines). Steam overwrites them the next time either mod updates. Both were subscribed 2025-04-14; update frequency unknown.
- B. A config-only fix mod: a folder in the game's local `Mods` directory holding a `.XComMod` descriptor and a `Config\XComContent.ini` that re-adds the 8 corrected entries. No SDK, no compile, survives workshop updates, and every later fix of this kind lands in the same folder. The launcher's `ModPaths` currently lists only the workshop folder, so the local `Mods` path must be added back in the launcher settings (it was present in the March database). Recommended.
- C. Do nothing. Six helmets and two leg decos stay invisible, the log stays noisy, nothing else changes.

Under read-only access jep drafts the folder into `projects/XCOM/fixes/` and Idi copies it into place. Under write access jep places it directly.

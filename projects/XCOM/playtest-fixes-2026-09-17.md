## Kill counter and combat log (issue 7)

Two different causes, neither a mod conflict. Extended Information Redux is off the suspect list, as Idi said.

1. Tactical UI Kill Counter Redux (2405013108): `RustyCounter_UI.uc` builds a 600 x 150 panel, anchor top-right (BoxAnchor 3), text RIGHT-aligned. Saved `OffsetX=-420` puts the panel's right edge 180 px past the screen edge, and right-aligned text lives at that edge. Factory value in `XComRustyCounter_Defaults.ini` line 113 is `-620`. The counter has been drawing off-screen since at least 09-16.
2. Battle Chatter combat log (3799514686): the mod ships its factory values as `XComBattleChatter_Defaults.ini`. The class is `config(BattleChatter)`, so the engine reads `XComBattleChatter.ini` and never that file (log line 5343: "unable to find DefaultBattleChatter.ini"). The engine wrote the Documents copy from class zero-values: `bEnabled=False`, `PanelAlpha=0`, empty colours, 8 px fonts. The MCM page has no Enabled box (checkbox list in `BC_MCMListener.uc` lines 146 to 425), so every tick Idi made was saved on top of a disabled mod. The mod's own author documents exactly this failure in the source (2026-09-16 note).

Fix, jep side, both in jepFixes (loads last, bare keys replace the saved values): `XComRustyCounter.ini` with `OffsetX=-620`; `XComBattleChatter.ini` with the mod's 69 factory keys, `bEnabled=true`, alpha 0.2, fonts 14, hide-when-empty off. Precedence of a mod ini over the Documents copy is the standard mod-config merge (medium-high confidence; every mod's `XComGame.ini` works this way).

Fallback if either panel is still missing after one launch (Idi's clicks, 30 seconds): Options, Mod Settings, Tactical Counter Redux, Offset X slider to -620, Save. Options, Mod Settings, Battle Chatter, the Reset layout button (it sets Enabled true in code and saves), then Save. Once MCM has saved good values, the two jepFixes belt files can go.

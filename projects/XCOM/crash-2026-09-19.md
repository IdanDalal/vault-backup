## Crash 2026-09-20 16:10, retaliation mission, the fail-fast family with its first dump

### Verdict

The fail-fast family is a stack overrun inside the UnrealScript virtual machine (the interpreter that runs every mod's script), on the main thread. The 28 GB dump shows an access violation in VM code at `XCom2.exe+0x1441BB` through a pointer assembled from two halves of neighbouring stack slots (the stack content is shifted by four bytes), then the stack-cookie check fires while Windows unwinds the smashed frame. The 09-16 14:11 access violation at `+0x10E6D5` carries the same thirteen return addresses in the same recursive order, so it joins this family; its "10 APEX frames" label from the 09-16 audit is withdrawn (those pointers sit inside the crash-handler region of that stack). Family size: 8 events (08-30, 09-13, 09-14, 09-16 14:11, 09-16 19:59, 09-18, 09-20 10:53, 09-20 16:10).

The mechanism that produces exactly this shape in UE3: each script call gets its local frame on the native stack, sized by the callee's compiled layout, while the caller writes parameters by its own compiled layout. Two mods compiled against different versions of a shared package disagree on a struct or function size and the write runs past the frame. Confidence medium: the mechanism is engine-documented and community-known, the specific pair of mods is not identified. The Phosphorus-effect spam from the prior run is not the cause: it ended 17 s before the crash, on a Burner-class soldier.

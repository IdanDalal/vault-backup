## 2. Chance baseline (`chance.py`)

- Chance = share of frames within +-k frames of a grid point (what random cut times would score). Exact coverage and a 2,000-trial simulation agree (22 % for KC, 60 fps, +-2 frames).
- avsync already prints a half-beat null on its whole-video table; its loud/quiet, per-plate and accept tables printed on-beat rates bare. `chance.py --accept accept-X.json` adds the column.

## 3. Glitch gate (`flash.py`)

- Rule: a frame (or two) jumps away from its neighbours by more than max(2, 4x the local median step) and the picture comes straight back. Cuts never trip it (they do not come back).
- Planted test (KC 20 s, 60 fps): red frame, splice frame, 2-frame stray, double exposure: 4/4 caught; the double exposure moved 4.7 against a median step of 1.67; 0 false alarms in 1,196 clean frames.
- KC upload (4K, 11,646 frames, incl. the 11-01 repaired join): 0 flashes. Engine `flips.ts` (>= 60/255 brightness jumps) stays; this adds any short-lived change.

## 4. Animatic gate (`animatic.py`)

## B. Segmented, resumable render (`kit-tools\render-seg\segrender.py`, built same day on Idi's "B next")

- Workflow (Idi 11-04): 1080p whole renders while working; one 4K master after finalization. Both run through segrender.
- Design (hyperframes, method only): frame-aligned segments, each one `render.ts video --noaudio` process (fresh Edge + dev server per segment); manifest keyed by a hash of the render options + engine source; a segment is reused only when hash, bytes and probed frame count match; failed segment retried (default 2) with a failure class; stream-copy concat; song muxed once as render.ts does; final frame count checked. Default 1,800 frames per segment (~80 min at KC 4K speed; KC died at frame 11,580 of one session).
- Engine untouched (render.ts already renders frames [round(from x fps), round(to x fps))).
- Seam test (KC 50-56 s, 1080p, 1 sample, 3 segments of 120): 360/360 frames; per-frame PSNR vs a one-pass render 44.2 dB average, 41.7 min, seams 42.4-43.6 (interior level; engine run-to-run noise ~43 dB); control with a one-frame offset 21.7 dB, so every seam is frame-exact; decoded audio MD5 identical; `flash.py` 0 flashes.
- Crash drill (`SEGRENDER_KILL`): segment 2 killed mid-run, logged FAILED, retried, finished; 360/360; no stray Edge processes.
- Resume: rerun reused 3/3 segments; one deleted segment re-rendered alone.
- 4K check (release settings `--samples auto --shutter 0.2 --scale 2`, KC 54-56 s, 2 segments of 60): first join 118/120 frames, caught by the frame-count check; cause = `-shortest` at the audio mux cutting video at AAC frame granularity (video-only concat had 120); fixed (audio padded then trimmed to the window, no `-shortest`); re-join 120/120, 1080p test still 360/360 with audio MD5 identical to the one-pass render.
- GPU memory at 4K: peak 22.5 GB of 24.5 GB (baseline 3.5 GB, so ~19 GB for the render with the default 2 workers); at 1080p 1 sample, peak 6.5 GB. Supports the memory-pressure prior for KC's context loss (still unproven). Tested `--workers 1` on the same window: peak 13.2 GB (vs 22.5), speed 0.99-1.32 fps (vs 1.08-1.49, ~10 % slower), 120/120. Recommendation for the 4K master: `--workers 1` (9 GB more headroom for ~10 % more time).
- 4K speed in that window: 1.08-1.49 fps (KC's whole-song 4K average: 0.38 fps).
- Per-segment startup ~12 s (browser + dev server).

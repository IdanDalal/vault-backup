## 2. The structural call: one pass per plate, every lens at once

All of it lands in the same 13 scene files (one file per plate). Two ways to cut the work:

| option | what happens | cost |
|---|---|---|
| **A (rec)** | each plate gets one merged work order: its Do-it items, the pinned notes, its efficiency cuts, its text effects, its organic changes, its lens events. One builder, one critic round, per plate | each file opened once; 1 full render at the end |

A needs the shared tools settled first (section 3, phase 1), because 13 builders inventing 13 fire effects would break the one-project look.

## 4. Parallel, local, and the 5 h limit

### What runs side by side

| runs together | why it works | limit |
|---|---|---|
| 2 plate builders | one scene file each, no shared edits | 2 at once: with 2 builders + critics a window lasts about 3.3 h (measured 11-05); 3 agents burned one in 20 min (10-27) |
| builders + renders, gates, frame sheets | scripts cost 0 tokens | one heavy GPU job at a time |
| non-adjacent plates per wave | neighbours share a seam; pairing far-apart plates keeps seams still while both are edited | seams checked at each wave's end |
| NOT parallel | the shared kit files (`_pa.ts`, `_pa-lens.ts`, the new text and organic kits) | phase 1 settles them; builders import them read-only |

### What goes to local models

| job | worker | check on it |
|---|---|---|
| read the on-screen text of every second of v3 (292 frames): repeated words, text that outstays its line | local text model (reads frames) | 20-frame calibration at 90 %+ against jep's eye first (standing rule, 10-25); it picks where jep looks |
| concept pictures for note 2 (fire lettering, neon, smoke, fractal type) before any code | local image models, about 4 s a picture | your eye; used as references for the look |
| numbers out of builder reports and gate logs into the queue file | local text model | jep spot-checks |
| small single-file tools to a spec and a test (the rigidity reading) | local worker | its test + jep reads the diff |
| scene code | no: the 10-22 pilot's whole-file rewrite drifted | |
| defects, taste, counting | no: 42-56 % on judged labels, guessed counts (10-25) | |

Sizing, plainly: the local model saves little here, my estimate 5-10 % of tokens (low confidence). It fills 23.6 of the 24.6 GB, so it runs in phase 0 and between waves, while no render is running. The real savers: scripts for everything countable, option A, briefs on disk, proof first.

Codex (ChatGPT plan, a separate quota): installed, **not logged in** (checked 11-16). It cannot run commands on this PC (Windows sandbox, measured 10-22), so it could only write patches that jep applies and gates. Candidate load: the 31 under-1-h items. Unproven on this engine.

### The 5 h limit

1. State lives on disk: one queue file, ids = the room's ids, status, commit. Any session resumes from it in minutes.
2. One item = one commit. A builder that dies at the limit loses only its open item.
3. By the clock: no new builder starts after hour 2 of a window.
4. Token-free jobs fill the dead time: renders, gates and frame sheets are queued before a window ends, so the next one opens on results.
5. Order inside a window: critics and jep's sweeps first (judgment), builds in the middle, renders last.
6. The room mirrors the queue: each of your 58 answers moves to fixing, then done, with jep's reply. Progress shows without a render.
7. Resume: one word from you per window. A scheduled wake at the reset is untested.
